# Question 2 — Object-Oriented Design Evaluation

The provided CourseRegistration class combines student identity, course data, tuition calculation, console output, file writing, confirmation, and logging. These responsibilities violate high cohesion and Arthur Riel's advice to distribute system intelligence and keep responsibilities focused. All fields are public, breaking encapsulation and allowing invalid state. Registering a student is tightly coupled to FileWriter and standard output; storage or messaging changes therefore require changes to this class. Hard-coded rates, broad exception handling, and confirmation even after failed storage can cause incorrect results. A better design separates domain entities, fee policy, storage, communication, and workflow coordination, with validation and error propagation.
